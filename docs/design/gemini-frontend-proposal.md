# SubCal Desktop 前端设计方案（Electron 交互预览阶段）

> **核验范围声明**：本方案基于已直接阅读的本地《SubCal-Desktop-V1-PRD.md》（全文 21 章）及随附的 `yetone/magpie` 用量页实机浅色参考图（`usage-zh-light.png`）完成设计。PRD 中引用的外部 GitHub 源码链接（如 `app.js`、`app.css` 等）及第三方官方文档链接在本次会话中未发起外部网络请求拉取，相关参数均以 PRD 已固化的规格与附图视觉事实为准。

## 一、设计结论

### 1.1 推荐方案与核心理由
面向容易被冗余信息分散注意力的用户，SubCal 桌面端采用 **“顶部四段式导航 + 概览页三层视觉漏斗 + 紧凑品牌卡片 + 右侧滑出式详情抽屉”** 的单窗口架构。

打开软件的 **前 3 秒内**，界面只用最直接的中文回答三个问题：
1. **近期要处理什么？**（顶部“待办与近期续费条”：只展示未来 7 天内扣费/到期、过了续费日待确认、或连接失效需处理的事项；没事时自动收起成一行安心提示）。
2. **订阅还有多久？**（每张卡片固定左下角展示“下次续费/到期日 + 剩余天数 + 来源性质”）。
3. **额度还剩多少？**（每张卡片右上角或主内容区用右对齐大字号等宽数字展示余额或窗口剩余百分比）。

**为什么保留顶部导航而不改侧边栏？**
- 遵循 PRD 04 章与 Magpie 参考基线：顶部居中胶囊分段导航（`概览` | `订阅` | `日历` | `连接`）释放了 100% 的水平宽度，在 1280px 基准宽度下能舒适排列 3～4 列品牌卡片；即使缩小到 960px 最小宽度或开启 Windows 150% 缩放，也能保证稳定的 2～3 列网格，不会因为左侧边栏占去 200px+ 导致卡片内数字和日期换行挤压。

### 1.2 现有 PRD 最值得保留与最需要收敛的地方

**最值得严格保留的设计（直接决定产品诚实度与防犯错）：**
1. **概念物理隔离**：续费日（扣钱）、有效期结束日（停用）、额度重置日（回血）绝不混用；API 钱包余额、Key 预算限额、会员周期窗口百分比绝不折算相加。
2. **缺失与异常状态的诚实表达**：“尚未获取”“供应商未提供”“不适用”“预计已重置，尚待核实”“剩余 35% · 2 小时前（过时）”与真实的“剩余 0% / ¥0.00”严格区分。
3. **Magpie 的高信息密度卡片基因**：真实品牌图标、左名右数（等宽数字右对齐）、同产品多账号内部分区、单卡独立刷新与来源时间戳。
4. **日历单向受管与三态反馈**：先预览后同步，严格区分“已排队 / 已写入 / 已读回确认”，外部修改触发冲突提示而非静默覆盖。

**前端阶段必须收敛与重组的点（防止信息过载与前置过度开发）：**
1. **合并“订阅列表”与“服务目录”，砍掉独立重型表格页的冗余感**：PRD 08.1（概览）和 08.2（订阅列表与目录）如果做成两个长得差不多的列表，用户会困惑“去哪改订阅”。本方案明确：**「概览」看卡片盯状态，「订阅」页做表格式批量管理与新增目录入口**，两页共用同一个右侧「订阅详情抽屉」和「新增/编辑弹窗」。
2. **克制顶部汇总数字，拒绝信息噪音**：不在首屏堆砌“四大统计大卡”。汇总信息压缩为卡片网格上方的一条 **轻量统计栏（高 36px）**，仅按币种分列（如 `月均固定支出：¥128.00 · $40.00 | 7天内续费 2 项 | 1 项费用待补充`）。
3. **收敛详情层级**：不在页面间来回跳转丢失上下文。点击任何地方的订阅卡片、表格行或日历事件，统一从右侧滑出 **440px 宽的详情抽屉**，关闭抽屉瞬间回到原位置。
4. **明确前端预览边界**：在顶部标题栏右侧固定一枚克制的琥珀色胶囊标签 `前端预览 · 外部服务未连接`，底部或操作处提供一键切换模拟场景（正常、过时、401 失效、日历冲突等）的“场景调试器”，不收集任何真实 API Key 或密码。

## 二、信息架构

### 2.1 顶部主导航与页面职责
全应用仅设 4 个主导航标签 + 1 个右侧设置抽屉入口 + 1 个顶部预览模式标识：

| 导航项 | 解决的核心问题 | 页面核心形态 |
| :--- | :--- | :--- |
| **1. 概览**（默认首屏） | “今天有没有快扣钱或快用完的？各家还剩多少？” | 顶部待办与近期续费提醒条 + 轻量筛选与币种汇总栏 + Magpie 风格品牌订阅卡片网格 |
| **2. 订阅** | “我一共录了哪些服务？怎么快速新增、筛选、批量改或删？” | 顶部搜索与“+ 新增订阅（含品牌目录）”按钮 + 结构化紧凑表格（支持多选暂停、导出、归档/删除） |
| **3. 日历** | “这个月哪几天要扣钱？外部 Google / Apple 日历同步对了吗？” | 左侧 65% 本地月视图 + 右侧 35% 近期日程流 & 外部日历同步状态/预演面板 |
| **4. 连接** | “哪几个自动查询断了？下次什么时候查？怎么切换模拟状态？” | 已配置的 5 类正式适配器 + 实验/手动说明卡片列表，展示账号、可读字段、心跳倒计时与排障动作 |
| **⚙ 设置**（右上角图标） | “怎么改深浅色、剩余/已用显示偏好、通知开关和备份恢复？” | 模态弹窗，分“显示与偏好、提醒规则、备份与导入预览、隐私与图标许可”四小节 |

### 2.2 信息分层规则（消除跨区域重复）
同一个事实只在一个层级承担主展示职责，绝不在全屏到处重复贴标签：

- **首屏（概览顶栏）只放“需行动项”**：未来 7 天内的续费/到期、已过计划续费日待人工确认、低于 20% 阈值的活跃额度、以及中断的采集/日历连接。如果某个订阅还有 22 天才续费且额度 80%，它**绝不**出现在顶部提醒区。
- **品牌卡片只放“当前快照”**：品牌图标+产品名、账号/套餐名、最多 2 个核心额度窗口（或分项余额）、下一次续费/到期日（含来源标签：如`手动确认` / `预计`）、最后成功采集的相对时间（如 `5分钟前 · 官方API`）和 1 个主动作按钮（当有异常时显示具体动作如`重连`，正常时仅保留微弱的单卡刷新图标）。
- **详情抽屉放“完整上下文与核对”**：全部额度窗口、共享池关联说明、开始日/试用结束日/取消生效日、手动锁定开关与自动采集值对比、最近 10 次真实变化快照列表、单订阅日历提醒开关、官网账单直达链接与删除入口。
- **连接页与诊断放“技术原因与恢复”**：适配器版本号、HTTP 状态码语义化说明（如 `429 触发频率限制，将在 14:30 后自动重试`）、运行时路径检查、脱敏诊断 JSON 预览与导出。首页卡片绝不展示错误码或长串英文报错。

### 3.2 区域尺寸、密度与滚动规则
- **固定不滚动区域**：
  - **顶部导航栏（高 56px）**：集成 Electron `titleBarOverlay`，预留 macOS 左侧 76px 红黄绿按钮安全区、Windows 右侧 138px 最小化/最大化/关闭按钮安全区。中间为分段导航，右侧为 `[+ 新增订阅]` 主按钮、全局刷新按钮与设置按钮。
  - **底部前端预览控制器（高 36px，仅前端预览阶段存在）**：固定在窗口最底端，浅紫灰底色，提供一键切换 12 种边界测试场景，避免测试者去改代码才能看异常状态。
- **主体垂直滚动区域（内边距 `20px 24px`）**：
  1. **焦点行动区（条件常驻，高约 88px～100px）**：横向排列最多 3 张高优行动小卡（超过 3 项可横向翻页或点“查看全部需处理”自动激活下方筛选器）。**当没有任何 7 天内续费、低额度或连接报错时，该区域折叠为一行 32px 的绿色温和提示条**：“✓ 近期无紧急续费，所有自动连接运行正常”。
  2. **过滤与诚实汇总栏（高 68px，含上下两行）**：第一行为胶囊筛选器 + 排序下拉 + `剩余 / 已用` 全局切换开关；第二行为小字号诚实汇总。
  3. **品牌订阅卡片网格**：采用 CSS Grid `grid-template-columns: repeat(auto-fill, minmax(340px, 1fr))`，卡片间距 `12px`。在 1280px 窗口下稳定展示 **3 列**（每张卡宽约 396px，信息舒展、绝不拥挤）；若用户在设置中开启“紧凑密度”，最小卡宽变为 `290px`，1280px 下可展示 **4 列**。

### 3.3 小窗口（960×640）与 150% 系统缩放适配策略
- **960×640 最小窗口**：Grid 自动变为 **2 列**（每列约 444px）；顶部导航栏中的“前端预览 · 外部服务未连接”长文本自动缩写为 `预览模式` 胶囊；顶部行动区改为显示 2 张卡片。所有字号保持不变（正文 13px/14px，核心数字 22px），绝不靠缩小字号硬塞列数。
- **Windows 150% DPI 缩放**：由于使用标准 CSS 逻辑像素与自适应 Grid，150% 缩放由 Chromium 原生矢量放大，布局行为与逻辑宽度缩小一致，图标使用内联 SVG 保证边缘锐利，进度条和分割线使用 `1px` 物理对齐，不会出现文字截断或按钮被挤出屏幕。

### 3.4 提示优先级与“何时不显示汇总”的严格规则
- **提示优先级排序**：`1. 已到计划续费日待确认 / 今明两天扣费` > `2. 自动续费开启且 7 天内扣费` > `3. 额度窗口或钱包余额低于阈值（且数据未过时）` > `4. 采集连接需重新登录 / 日历同步冲突` > `5. 续费日期未知需补充`。
- **不显示或排除汇总的硬规则**：
  1. **没有任何有效周期订阅时**（例如空白初始态，或用户只录入了 DeepSeek / Kimi 等按量充值的 API 钱包），隐藏“固定周期月均支出”和“未来 30 天已知扣费”，直接显示 `当前仅记录按量 API 钱包，无固定周期月费`。
  2. **多币种绝不混加**：同时存在人民币（`¥`）、美元（`$`）订阅时，并列显示 `¥98.00 + $40.00`，绝不按假汇率合成一个总数。
  3. **疑似共享余额不加总**：如果用户录入了两个同一供应商的 API Key 且未确认是否为不同账户，不提供“API 钱包总余额”汇总，防止翻倍误导。
  4. **未知价格显式单列**：若有 2 个订阅未填价格，汇总栏末尾必须紧跟琥珀色提示 `（另有 2 项未填写价格，未计入）`。

## 四、品牌订阅卡片设计

遵循 Magpie 的“左标识、右大数、紧凑分段”视觉骨骼，同时植入 SubCal 必需的“续费日期与数据来源诚实性”。所有卡片均遵循 **5 层垂直结构**：`① 卡片头（品牌+产品+状态）` → `② 账号与套餐副标题` → `③ 核心计量区（额度条或右对齐余额）` → `④ 底部续费与有效期锚点区` → `⑤ 页脚来源、新鲜度与动作栏`。

### 4.1 类型一：多窗口额度卡（以 Codex / GitHub Copilot 为代表）
适用于通过官方本地客户端或 SDK 读取多时间窗口百分比的编程/会员工具。

```text
+-------------------------------------------------------+
| [OpenAI 图标] Codex                        [正常] [↻] | <- 1. 品牌图标(20px)+产品名 | 状态徽章+单卡刷新
| 账号: niilo@example.com (个人) · ChatGPT Plus 权益    | <- 2. 账号别名/组织/地区 · 套餐名称 (12px 灰字)
|-------------------------------------------------------|
| 5小时窗口 (短窗)                             剩余 35% | <- 3. 窗口名(左) + 等宽大数字(右, 20px 加粗)
| [███████░░░░░░░░░░░░░]             今天 21:00 重置    |    进度条(高6px) + 精确重置时间(绝不叫续费!)
|                                                       |
| 周窗口 (7天)                                 剩余 62% |
| [████████████░░░░░░░░]         10月23日(周五) 重置    |
|-------------------------------------------------------|
| 📅 下次续费: 2026-11-03 (14天后) · $20.00/月 · 自动续 | <- 4. 续费安排(独立背景色块, 与上面重置日物理隔离)
| 🔒 日期来源: 手动锁定确认  |  ⚡ 额度: 2分钟前 · 官方端| <- 5. 两个字段各自独立的来源与新鲜度时间戳
+-------------------------------------------------------+
```
- **关键边界表达**：
  - 当某个窗口返回官方定义的无限量特殊值（如 Copilot 基础补全）：右侧大字位置显示 `无限量`（16px 紫色标签），下方不画假 100% 进度条，显示 `供应商标记此项无次数上限`。
  - 当重置时间已过（如已过 21:00）但尚未完成新一次采集：数字变为半透明灰字 `预计已重置，尚待核实`，进度条置灰虚线，右侧显示 `[立即核实]` 按钮，绝不自动脑补成 `剩余 100%`。

### 4.2 类型二：API 钱包与 Key 预算卡（以 DeepSeek / Kimi API / OpenRouter 为代表）
严格复刻 Magpie 用量页的右对齐大号货币数字感，同时拆清“现金 / 赠送金 / 代金券”与“Key 限额 vs 账户总资金”。

```text
+-------------------------------------------------------+
| [DeepSeek 图标] DeepSeek 开放平台          [正常] [↻] |
| 账号: 主力研发账户 (sk-...8f2a) · API 钱包            |
|-------------------------------------------------------|
| 可用总余额                                    ¥86.40  | <- 24px 等宽粗体右对齐，完全对齐 Magpie 视觉重心
| 充值现金: ¥76.40   ·   赠送余额: ¥10.00               | <- 分项明细清晰并列，不吞没构成
|-------------------------------------------------------|
| 📅 续费安排: 不适用 (按量预付钱包，无固定月度扣费日)  | <- 明确标为“不适用”，不伪造续费倒计时
| 🔌 来源: 官方 API · 12分钟前更新          [官网充值↗] |
+-------------------------------------------------------+
```
- **OpenRouter 当前 Key 的特殊诚实表达**：
  - 主数字左侧标题必须写 **`当前 Key 剩余预算`**（如 `$23.75 / $50.00`），副标题注明 `已用 $26.25 · 每月1日重置 Key 限额（非账户总现金余额）`。如果该 Key 的 `limit` 为 `null`（未设上限），则展示 `当前 Key 累计已用 $26.25 · 未设 Key 限额（普通 Key 不返回账户总余额）`。

### 4.3 类型三：纯手动会员卡（以 Claude Pro / Cursor 个人版 / 自定义服务为代表）
解决 PRD 核心要求：“手动记录 + 额度暂不可自动读取”是完整且诚实的一等公民状态，绝不显示成丑陋的报错或 `0%`。

```text
+-------------------------------------------------------+
| [Claude 图标] Claude Pro                 [手动记录]   | <- 徽章为平静的蓝灰色“手动记录”，不是红色报错
| 账号: work@example.com · Pro 月度订阅                 |
|-------------------------------------------------------|
| 额度与用量                           暂不支持自动读取 | <- 诚实说明，不画 0% 空进度条
| 上次手动记录: 5小时窗口约剩 40% (10月19日 18:20 粘贴) | <- 若用户粘贴过 /usage 文本，带时间戳展示作为参考
|-------------------------------------------------------|
| 📅 下次续费: 2026-10-22 (2天后) · $20.00/月 · 自动续  | <- 手动卡的视觉重心是续费日与账期！高亮提醒
| ✋ 来源: 用户手动确认 (10月01日核对)  [去官网账单页↗] |
+-------------------------------------------------------+
```

### 4.4 多账号、同品牌不同产品与共享额度池的显示规则
1. **同品牌不同产品（如 ChatGPT 会员 vs OpenAI API，Kimi 会员 vs Kimi API 国内站）**：**分卡独立显示**。因为计费方式、数据源、周期完全不同，强行塞进一张卡会导致钱包余额和会员续费日混在一起。
2. **同一产品的多个账号（如 2 个 Codex 账号，或 2 个 DeepSeek 账户）**：采用 Magpie 的 **同卡内部分区折叠模式**。
   - 卡片头部显示 `[Codex] · 2 个账号`。
   - 卡片内部默认上下分栏展示两个账号各自的“账号别名 + 核心剩余额度 + 各自续费日”。超过 2 个账号时，默认展示前 2 个（或最紧急的 2 个），底部提供 `展开其余 1 个账号 ▾`。
3. **共享额度池（Shared Quota Pool）表达**：
   - 当用户将“ChatGPT Plus 网页端（手动）”与“Codex 本地端（自动）”关联到同一个订阅/额度池时，两处或合并卡中会显示一枚浅紫色胶囊：`🔗 与 ChatGPT Plus 共用同一 $20/月 订阅账期`。
   - 在顶部月均支出汇总和日历事件生成中，共享同一订阅账期的记录 **只计算 1 次费用、只生成 1 组日历续费事件**；如果两个 API Key 被标记为“同一账户下的不同 Key”，第二张卡金额旁标注 `（与主 Key 共享账户余额，不重复计入汇总）`。

## 五、关键交互与操作路径

### 5.1 为什么选“右侧详情抽屉”而非跳转独立详情页？
ADHD 用户最怕“点进去看了一眼详情，退出来忘了刚才看到哪张卡”。
- **交互决定**：点击「概览」的任意卡片、「订阅」页的任意表格行、或「日历」页的任意事件气泡，统一从窗口右侧滑出 **宽 460px 的详情抽屉（Drawer）**。左侧主视图保持原滚动位置并轻微变暗（遮罩可点击关闭，或按 `Esc` 键关闭）。
- **新增与编辑**：采用居中模态对话框（宽 560px，分“基础与收费”“额度与自动连接”“日历与提醒”三段清晰表单，一屏可见，无需繁琐的 6 步跨页向导）。

### 5.2 四条核心闭环路径（从发现问题到处理完毕）

#### 路径 A：发现 2 天后续费 → 去官网退订 → 回到 SubCal 改状态并更新日历
1. **发现**：打开软件，概览顶部焦点区第一张卡显示 `📅 Claude Pro · 2天后续费 ($20/月)`。
2. **行动**：点击卡上的 `[去官网处理↗]`，系统调用默认浏览器打开已校验 HTTPS 的官方账单页；同时右侧自动滑出 Claude Pro 的详情抽屉，停留在“等待你在官网操作后确认”提示条。
3. **确认更改**：用户在官网取消自动续费后，回到抽屉直接点击一键快捷动作 **`[我已在官网取消自动续费]`**。
4. **诚实变更预演**：弹出轻量确认框：
   - 订阅状态将由 `有效（自动续费）` 改为 `计划到期不续费`；
   - 当前已付有效期保留至 `2026-10-22`；
   - **日历影响预览**：将移除 11 月及之后的 11 个“预计续费”日程，并在 `2026-10-22` 生成 1 条“Claude Pro 到期停止”日程。
   - 底部明确一行小字：*“注：此操作仅更新 SubCal 本地记录与受管日历，不会代替你在供应商网站执行退订。”*
5. **完成**：点击确认，顶部紧急扣费提醒消失，卡片变为温和的 `10月22日到期停用`。

#### 路径 B：到了计划续费日但无自动依据 → 人工核对确认
1. 当日期到达 `10月22日` 且该订阅为手动记录（或自动接口不返回账单日），卡片绝不自己偷偷把下次续费改成 `11月22日`。
2. 卡片状态变为琥珀色 **`已到计划续费日，待确认`**，并提供两个直接按钮：`[确认已续费，顺延至 11月22日]` 和 `[已停订/改期]`。点一下即完成顺延并保留 `1月31日 -> 2月28日 -> 3月31日` 的锚点规则。

#### 路径 C：自动采集报错（如 401 登录过期 / 429 限流 / 缺少本地 CLI）→ 恢复
1. 卡片保留最后一次成功的额度值（例如 `剩余 35%`），但在时间戳处显示琥珀色 `2小时前 · 认证已过期`，右上角状态变为 `[需重新登录]`。
2. 点击 `[需重新登录]`，弹出连接恢复面板（在前端预览阶段为“模拟授权探测弹窗”）：
   - 显示具体原因：“官方客户端会话已过期（错误分类：AUTH_REQUIRED），旧额度数据已保留，未清零。”
   - 提供两个动作：`[模拟重新连接并探测字段]` 或 `[暂停自动采集，仅保留手动续费提醒]`。
3. 点击模拟重连后，经历 800ms 模拟探测动画 → 展示探测到的账号身份与字段预览 → 点击确认后卡片恢复 `刚刚更新 · 官方本地端`。

#### 路径 D：删除订阅的防误删与恢复体验
1. 在详情抽屉底部点击 `[删除记录]`，弹出明确的范围选择框（非简单确定/取消）：
   - 选项 1（推荐）：**归档并停止追踪**（移入归档筛选，保留历史观察，清理未来日历事件）。
   - 选项 2：**彻底删除本地订阅记录**，并勾选 `☑ 同时从已连接的 Google / Apple 日历中移除未来由 SubCal 创建的受管事件（不影响过去事件与私人日程）`。
2. 执行删除后，窗口底部浮出 **8 秒可撤销 Toast**：`已删除「Cursor Pro」及 12 条未来受管日程  [撤销恢复]`。在预览阶段点击 `[撤销恢复]` 可完整还原刚才的记录与日程。

### 5.3 键盘导航、焦点管理、未保存修改与空状态
- **键盘与焦点**：
  - `Tab` / `Shift+Tab` 顺序严格遵循：顶部导航 → 焦点行动区按钮 → 筛选栏 → 卡片网格（卡片内部仅整卡本身和刷新/动作按钮可聚焦，避免一张卡按 10 次 Tab） → 底部场景条。
  - 在卡片网格中支持方向键 `←` `→` `↑` `↓` 移动焦点，按 `Enter` 或 `Space` 打开右侧详情抽屉，按 `Esc` 关闭抽屉并将焦点精准退回刚才那张卡片。
  - 卡片顺序调整：除鼠标拖拽左上角手柄外，聚焦卡片时按 `Alt + ← / →` 可直接前移/后移卡片顺序，并实时持久化到本地状态。
- **未保存修改保护**：在新增/编辑弹窗或详情抽屉中修改了价格、日期或备注但未点保存时，若点击遮罩或按 `Esc`，表单抖动并高亮底部提示条：`有未保存的修改：[保存更改]  [放弃修改]`，不直接丢弃用户输入。
- **首次空白状态（Empty State）**：当列表为空时，概览页不展示空荡荡的灰色格子，而是居中展示一张清晰的引导卡：
  - 标题：**“先花 1 分钟把正在付钱的 AI 服务记下来”**
  - 说明：“不需要准备 API Key 也能用。你可以先从常见品牌目录添加订阅、记下续费日；支持自动查询的 5 项服务（Codex、Copilot、DeepSeek、Kimi API、OpenRouter）随时可以补连。”
  - 两个大按钮：`[+ 从品牌目录添加第一项订阅]`、`[加载演示数据集（含 8 条典型场景）]`。

## 六、日历与同步表达

### 6.1 「日历」页双栏并存布局（左月历 65% + 右日程与同步工作台 35%）
- **左侧本地月视图（占宽约 760px）**：
  - 顶部为月份切换（`◀ 2026年 10月 ▶`、`[回到今天]`）以及事件类型勾选过滤：`[☑ 续费扣款]` `[☑ 到期/试用结束]` `[☑ 开始日]` `[☐ 额度重置点（仅本地按需显示）]`。
  - 每个日期格最多直接展示 **2 条事件胶囊**，超出时显示 `+2 项更多`，点击格子在右侧面板定位到当天详情，绝不把图标缩成看不清的麻点。
- **四种事件类型的“文字前缀 + 图形符号 + 色彩”三重区分（兼顾色盲与高对比度）**：
  1. **`[￥ 续费]`（实心紫蓝胶囊）**：例如 `￥ Claude Pro 续费 $20`（若为推算未核实，前缀写 `￥[预计] Claude Pro 续费`）。
  2. **`[⏹ 到期]`（琥珀色描边胶囊，带斜线纹理）**：已取消自动续费后的有效期结束日，或试用结束日，例如 `⏹ Cursor 试用结束`。
  3. **`[▶ 开始]`（浅灰小圆点胶囊）**：订阅初始生效日，仅作历史坐标，不发打扰通知。
  4. **`[↻ 重置]`（青色虚线胶囊，默认关闭）**：仅当用户主动开启某周窗口的本地日历展示时出现，且明确标注 `[仅本地·不写外部日历]`，绝不触发扣费提醒。

### 6.3 避免“假成功”：四步状态流转与冲突裁决界面
在前端预览中点击 `[预览待同步变更]` 再点击 `[执行模拟同步]` 时，界面通过真实的阶段状态机展示，绝不一点按钮就弹“同步成功”：
1. **同步前必须先看「变更预演清单」**：列出本次将 **新增（+1）**、**修改日期（~1，沿用原稳定事件 ID `subcal_occ_042`）**、**移除未来预计（-3）** 的具体日程，并声明：`默认仅写入产品名、事件类型、预计/已确认性质与价格；不包含邮箱、API Key 或剩余额度。`
2. **三态进度流转徽章**：
   - `⏳ 已加入本地 Outbox 队列 (1/3)` →
   - `📤 已写入目标日历，等待远端读回校验 (2/3)`（若是 macOS EventKit 写入 iCloud 日历，此处文案严格显示为：`✓ 已写入本机系统日历 · iCloud 云端同步由 macOS 系统后台负责`） →
   - `✅ 远端读回核对一致 (3/3)`（仅在此时才变为绿色完成态）。
3. **外部修改冲突裁决卡片**：
   - 当模拟“用户在手机日历里把 Claude 续费从 10月22日 拖到了 10月25日”时，卡片显示对比：
     - `SubCal 本地记录：10月22日` vs `外部日历被改为：10月25日`
   - 提供三个清晰动作按钮：
     - `[以 SubCal 为准，覆盖回 10月22日]`
     - `[采纳 10月25日 为新的手动计划日]`
     - `[解除此事件管理（保留外部日程，SubCal 不再更新它）]`

### 7.2 字体与排版层级
- **字体栈**：
  - macOS：`-apple-system, BlinkMacSystemFont, "PingFang SC", sans-serif`
  - Windows：`"Segoe UI Variable Display", "Segoe UI", "Microsoft YaHei UI", sans-serif`
  - 数字专用：`font-variant-numeric: tabular-nums`（所有金额、百分比、倒计时天数、日期强制开启等宽数字特性，保证上下对齐、刷新时不抖动）。
- **字号梯度**：
  - **22px (`font-weight: 700`)**：卡片右上角核心余额（`¥86.40`）或单窗口剩余百分比（`35%`）。
  - **16px (`font-weight: 600`)**：双窗口并列时的剩余百分比、页面区块小标题。
  - **14px (`font-weight: 600`)**：卡片品牌与产品名、表格主字段、按钮文字。
  - **13px (`font-weight: 400`)**：卡片内续费安排正文、窗口名称、表单标签。
  - **12px (`font-weight: 400`)**：账号别名、来源标签、相对时间戳（**全应用最小字号不得小于 12px**）。

### 7.3 卡片尺寸、留白与图标规范
- **卡片容器**：圆角 `10px`，边框 `1px`，内部四周内边距 `14px 16px`，卡片之间间距 `12px`，阴影仅使用极淡的 `0 1px 2px rgba(0,0,0,0.03)`，靠灰底白卡的明度差建立秩序。
- **品牌图标处理**：
  - 卡片头图标固定 `20×20px`，详情抽屉头图标 `28×28px`。
  - 随前端包内置一套已核实 MIT / 官方品牌指南许可的本地静态 SVG 图标组件（OpenAI/Codex、Anthropic/Claude、DeepSeek、Kimi、OpenRouter、GitHub Copilot、Cursor、Google Gemini 等），支持深色模式自动反色或切换浅色路径。
  - **文字后备（Fallback）**：对于自定义服务或未获图标分发授权的品牌，生成带有品牌首字母/简称的 `20×20px` 圆角方形几何徽标（固定配色哈希），绝不发起外部不明图标 URL 请求，也绝不用随意 Emoji 充当正式品牌图标。

### 7.4 如何参考 Magpie，以及哪些有意不照搬
- **完全吸收自 Magpie 的优秀设计**：
  1. 顶部居中灰底胶囊分段导航与浅灰窗口底色（`#F4F4F6`）。
  2. 白色圆角品牌卡片中“左上角图标+粗体品牌名，左下角灰字维度，右下角大号粗体等宽货币/数字”的视觉重心（如附图中 DeepSeek `¥86.40`、Kimi `¥142.10`、OpenRouter `$23.75` 的排布）。
  3. 同一供应商多账号在同一张卡内分组折叠、多额度窗口进度条与单卡独立刷新按钮。
- **有意不照搬的部分及原因**：
  1. **不照搬附图右上角的 `≈$76.59 标价` 折算大总数**：SubCal 同时管理月费订阅、预付钱包和百分比额度，且横跨人民币与美元，强行折算成一个美元总数违反硬约束 2 和 4，会产生严重的财务误导。
  2. **不照搬附图中间的 `23M TOKEN / 158M 缓存读取 / 0 推理 / 705 次调用` 四格统计卡**：SubCal 不是本地 API 网关代理，不拦截用户的每次对话请求，没有全量调用日志来源，绝不伪造无数据源的统计卡。
  3. **不照搬附图底部的每日紫色柱状消耗趋势图**：同理，V1 仅按心跳周期采样剩余额度快照，不具备按天统计 Token 吞吐量的原始数据，因此在原柱状图的位置改为呈现 SubCal 的核心价值——**含续费日期锚点与来源说明的完整品牌订阅卡片网格**。

### 8.2 前端异步数据服务接口（`SubCalFrontendService`）
前端所有交互不直接散落修改组件 `useState`，而是通过一层与 PRD 15.2 业务 IPC 签名完全同构的内存异步服务（带 200ms～600ms 可感知的加载状态与 `revision` 乐观并发检查，并持久化到 `localStorage` 以便重启窗口保留演示编辑结果，同时支持一键重置回初始预设）：

### 8.3 必须内置覆盖的 12 个确定性模拟场景
底部「预览场景控制器」及默认数据集直接内置以下 12 种真实边界状态，无需修改代码即可逐项点击检验：
1. **`empty_first_run`（首次空白）**：0 条记录，展示新手引导与一键加载演示数据。
2. **`normal_mixed`（标准混合常态，默认启动场景）**：包含 Codex（双窗口）、Copilot（含无限量项）、DeepSeek（人民币现金+赠送金）、OpenRouter（美元 Key 预算）、Claude Pro（纯手动快到期）、ChatGPT Plus（与 Codex 共享池）。
3. **`multi_account_shared`（多账号与共享池）**：Kimi 卡内含 2 个账号折叠；2 个 DeepSeek Key 展示“疑似同账户共享余额，不重复汇总”。
4. **`unknown_and_na`（未知与不适用）**：新录入的自定义服务未填续费日（显示“续费日期待补充”）；API 钱包续费日显示“不适用”；Claude 额度显示“供应商未提供此项”。
5. **`real_zero_vs_unfetched`（真实零值 vs 尚未获取）**：一张卡展示 `余额 ¥0.00`（触发红色低额度提醒），另一张刚建档未刷新的卡展示 `尚未获取`（中性灰，不告警）。
6. **`stale_and_past_reset`（数据过时与已过重置点未复查）**：额度快照停留在 3 小时前（标为 `过时·待更新`）；短窗口重置时间已过 15 分钟但未复查（标为 `预计已重置，尚待核实`）。
7. **`partial_success`（同次采集部分成功）**：余额字段更新为 `刚刚`，但套餐字段解析失败保留 `昨天` 的时间戳，卡片底部诚实标注部分更新。
8. **`auth_expired_401`（认证失效与手动锁定差异）**：连接进入 `需要重新登录`；同时演示自动探测到的续费日（11月5日）与用户手动锁定日（11月3日🔒）并存对比，不静默覆盖。
9. **`rate_limited_429`（触发频率限制）**：点击刷新时提示 `已合并请求 / 供应商限流中，下次允许查询时间 14:35`，旧值完好保留。
10. **`offline_wakeup`（离线与休眠恢复）**：顶部显示离线横幅，所有自动卡片停止倒计时但可正常浏览和手动编辑；点击“模拟恢复联网”演示合并补查一次。
11. **`date_boundary_leap_dst`（月末锚点、闰年与已到续费日待确认）**：包含 1月31日 锚点在 2月28日 的排期表现、跨时区全天事件不偏移、以及到了今天续费日显示 `已到计划续费日，待确认`。
12. **`calendar_conflict_and_stages`（日历三态流转与外部修改冲突）**：演示 `已排队 -> 已写入 -> 已读回` 全过程，以及 Google Token 7 天测试期到期提示、iCloud CalDAV 远端事件被外部改期后的三选一冲突裁决。

### 9.2 本方案对现有 PRD 的必要调整清单
以下调整不改变 PRD 的业务底线与安全承诺，仅修正开发排期顺序与界面信息组织方式，建议在进入开发时同步更新至 PRD 记录：

1. **调整第 17.1 节「执行顺序」**：
   - **原 PRD**：P0 先做真实账号与 CalDAV/EventKit 技术验证 → P1 做 SQLite 骨架 → P4 才做完整界面与 Magpie 对照。
   - **调整决定**：新增 **P0.5「可交互桌面前端预览阶段」**（置于真实后端、SQLite 与外部 API 接入之前）。先在真实 Electron 窗口中用确定性模拟服务跑通全部页面、卡片密度、日期语义与异常状态机，让用户先看清、点通、改顺，再将 `SubCalFrontendService` 背后替换为真实 IPC + SQLite + 采集进程。
2. **调整第 08.1 与 08.2 节「概览、订阅列表与目录的关系」**：
   - **原 PRD**：概览、订阅列表、目录、订阅详情分节描述，未明确详情载体。
   - **调整决定**：明确主导航固定为 `概览 | 订阅 | 日历 | 连接` 四项；品牌目录内嵌于「新增订阅」流程与「订阅」页顶部；「订阅详情」统一采用 **右侧滑出抽屉（Drawer）** 而非独立跳转页面，减少跨页迷失。
3. **补充第 08 章「前端预览模式防误导规范」**：
   - **新增规定**：在未连接真实后端的预览构建中，窗口顶栏常驻 `前端预览 · 外部服务未连接` 标识，所有连接表单禁用真实密码/API Key 文本输入（改为选择预设模拟凭据档案），防止用户在预览阶段误填真实密钥或误以为已向外部日历完成真实写入。
