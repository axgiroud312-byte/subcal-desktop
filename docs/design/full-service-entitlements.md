本次是任务规划，尚未改动运行中的前端。用户附件未能作为图片读取；依据已实际读取的 Magpie 仓库截图 `site/public/img/usage-zh-light.png` 及 `internal/gui/assets/app.js` / `app.css`，不声称已逐像素对齐用户附件。

## 已核对参考

固定提交 `ba319a7587923fc7a4ea3859658244d591261a59`：`renderQuotas`（app.js 15380 起）按供应商组合多账号；`planSpan`（16454 起）展示套餐及 until/renew；`balanceRow`（17781 起）余额分项；`readWhen`（17823 起）实际读取时间；`familyQuota` / `quotaWindows`（17940 / 18029 起）模型家族与动态窗口。app.css 809—818：自适应网格最小列宽 260px、间距 7px、卡片内边距 10/12/11px、圆角 10px；这些是上游参考几何，不是新的共享 Token 值。

## 推荐页面结构

顶部保留 SubCal 导航和新增入口；主区采用紧凑自适应卡片网格。每卡标题为图标、服务名、更新操作；其下是账号/工作区与套餐。会员日期单独一行，明确“有效至”“将续费”“下次账期”，绝不把额度重置写成到期。

每个窗口展示：可读名称、剩余/总量或已用百分比、细进度条、实际重置时间；模型共享窗口合组，不重复累计。余额显示独立金额分项，OpenRouter 账户余额和 Key 预算分别命名。付款金额降为可编辑次要行，不抢占权益主体。

多账号按来源身份稳定排序并可展开；无权益数据时显示正在查询或上次失败，仍保留卡片。部分失败保留成功项与上次时间，重登入口就近；不用内部错误码、适配器 ID、availability 枚举当文案。

历史区参考 `quotaCurve`（app.js 16205 起）：展示实际“剩余额度随时间变化”，按窗口图例区分，支持当前周期/已有历史周期。重置后的补满点属于下一周期，不连线成同周期内增加；读取间隙保留间断。匀速参考线、预测耗尽时间必须明确标为估算，不能用于填写会员到期或真实账单。没有足够观察点时隐藏曲线而不是画默认走势；Magpie 自身模型请求统计不混入供应商权益。

## 复用与实现依据

- Token 唯一来源：`src/renderer/styles/tokens.css`；沿用 `--card`、`--foreground`、`--muted-foreground`、状态色、间距和圆角；新增密度变体也在该源码集中维护。
- 组件基线：`components.json` 的 base-mira / Base UI，现有 Button、Modal、Field、Input、Badge、QuotaMeter；`SubscriptionCard.tsx` 组合扩展，不引入第二套 UI 框架。
- 图标沿用 lucide 与 BrandIcon；现有 Recharts 仅用于真实观察曲线。拖拽沿用现有 dnd-kit，不复制 Magpie DOM 操作。
- 实施样板入口：`SubscriptionCard.tsx` 与 OverviewPage；先以明确标注的设计夹具覆盖多窗口、多账号、余额分项和未知日期，再接真实采集。夹具不得混入生产数据或宣称账号成功。

## 可观察验收

真实 Electron 1280 与 960 宽度检查：长中文、多个窗口、多账户及局部失败不溢出；卡片内容按实际字段增减，无强制空块。键盘可操作加入/更新/支付金额编辑，状态反馈不抢焦点。对照固定版 Magpie 截图记录网格列宽、间距、卡片内边距、信息顺序差异；保留 SubCal 可读字号而非机械压缩为上游 11px。日期无精确时刻不显示虚假倒计时。
