# 账号连接优先的新增流程

> 已被用户进一步纠正：本页记录的 FE-020 仍含“读取后确认”，没有满足自动发现凭据及加入后自动查询的需求。当前有效规格为 [账号接入与自动订阅识别](../specs/account-access.md)，术语以 [GLOSSARY](../../GLOSSARY.md) 为准。以下仅保留历史设计和验证证据，不作为当前实现目标。

依据：用户 2026-10-21 对新增订阅表单的纠正。原表单把指标结构直接暴露为用户配置，这是入口设计错误，不是缺少读取接口。

## Magpie 源码核对

实际读取 yetone/magpie 提交 `ba319a7587923fc7a4ea3859658244d591261a59`：

- `internal/gui/assets/app.js`：`discoverLocalProviders` 从后端获取本地配置发现结果，`openImportApps` 让用户选择导入，前端只见掩码；添加 provider 先选供应商/登录方式。
- `internal/provider/subscription_usage.go`：`SubscriptionQuota` 描述账号、套餐、余额和 `Windows`；`QuotaWindow` 的名称、用量、单位、重置来自供应商读取结果。用户不用创建“5 小时额度”或配置 `availability`。
- `internal/provider/codex_limits.go`：按窗口时长匹配服务端报告的额度与重置时间，更新已有观察；不是用户填写额度模型。

Magpie 还提供代理请求、账号配置导入及部分非公开采集路径。这里只借鉴“连接身份后自动展示”的操作流程；SubCal 继续使用已选定的官方只读适配器，不复制认证文件或非公开接口，也不发送推理请求。

## SubCal 修正

1. 全局新增、空状态新增先展示服务选择。
2. Codex/Copilot 选择后读取本机已登录账号；HTTP 服务输入 API Key。
3. 后端归一化账号、套餐和全部返回额度，用户确认即自动创建订阅并启用更新。
4. 手动记录作为独立入口，只补无法读取的账单事实；不预填套餐、价格或额度桶。
5. 修改账单资料保留原采集指标、来源、观察时间和重置时间，不重新制造观察值。

官方接口未返回的真实付款金额/续费日不会根据额度周期猜测，仍可在需要日历提醒时补录。

验证：真实 Electron 从全局新增选择 Codex → 官方只读查询 → 确认添加 → 自动显示订阅额度已通过；没有填写指标字段。账号数据只存于隔离测试资料库，测试后已删除。
