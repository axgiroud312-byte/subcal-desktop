# 账号接入与自动订阅识别

状态：BE-012 代码接入已交付，Codex 已有登录真实流程通过，其余真实条件见 [验证记录](../evidence/BE-012/acceptance.md)，用户验收 pending。术语唯一正文在 [GLOSSARY](../../GLOSSARY.md)，参考实现事实在 [源码核对](../references/account-access-source-review.md)。

## 实施决定：优先移植成熟实现

用户进一步明确允许直接复用 Magpie / CC Switch 代码。当前执行任务为 [BE-012](../issues/BE-012.md)，接替 BE-011。按固定源码版本移植凭据发现、OAuth、刷新协调和权益解析，保留 MIT 声明；Go/Rust 逻辑适配当前 TypeScript 架构，不再独立发明账号接入流程。

Codex/Copilot 取得有效凭据后直接请求对应权益端点，不把 App Server/SDK 运行时作为唯一前置。Claude 主路径采用 CC Switch 的本地 OAuth 凭据与用量端点，Magpie CLI /usage 只作明确的兼容后备。API 服务优先导入已支持配置中的 Key。用户加入后自动查询，无第二次读取/确认操作。

## 目标与用户流程

打开添加入口自动发现本机已有账号；用户选择加入，或完成登录/填写 Key。随后后台自动保存账号、建立订阅、获取权益、生成卡片并开启更新。没有“读取账号”“探测字段”“确认绑定”第二道流程。查询暂时失败仍保留账号，并显示可恢复状态。

已有凭据优先复用，能从支持来源读取的 Key 不再让用户重复填写。接口没有返回的账单金额/续费日期才允许补录。来源、账号身份、必要授权说明保留；技术字段、指标编辑和无关小字不暴露。

## 职责

- 账号发现服务：只读支持来源，返回账号候选及来源摘要，不向 Renderer 发送秘密。
- 登录/凭据服务：处理 OAuth、API Key、来源引用、系统加密、外部登录跟随和托管登录；账号身份与凭据版本分开建模。
- 权益查询服务：按服务及凭据种类自动选择已验证策略；采用源码核对中的直接查询或兼容客户端方式，客户端运行时不再是统一前置。
- 本地业务服务：幂等添加账号并关联订阅；查询失败不回滚账号加入，不制造重复卡片。保留原手动账单和历史观察。
- 更新调度：启动/唤醒/凭据变化自动协调，远端请求按服务限频；401 恢复登录、429 退避、字段变化保留旧观察。
- 界面：账号发现、登录/Key 输入、添加结果；只展示实际权益，不让用户操作适配器流程。

## 当前范围

Codex、Claude Code、Copilot、DeepSeek API、Kimi API 国内站、OpenRouter。多账号与工作区分别识别。外部日历写入、推理代理和自动替换其他客户端默认账号不属于此任务。

保留已有 SQLite、safeStorage、后台隔离和调度基础。允许用户本人已有登录凭据的发现/读取与支持格式的导入；不再执行旧版“一律不读取认证文件”的约束。客户端内部接口允许作为接入策略，但必须标注来源、版本与真实验证情况，不冒充公开稳定合同。

## 共同规则

- 凭据只用于用户加入的账号；日志、普通备份、诊断及 Renderer 无明文凭据。
- 外部登录与托管登录分别管理刷新责任，刷新串行、代次校验、原子持久化；不覆盖来源中较新的凭据。
- 同邮箱不同工作区不合并；同一账号多来源去重；账号切换不能让旧结果串到新账号。
- 数据来自实际返回，未知不归零；余额、Key 预算、额度与账单日期分开。重置后不能自行填满额度。
- 只查询身份与权益，不创建推理请求或消费积分。移除账号不注销原客户端，也不删除其配置文件。

## 当前实现合同

`accounts.discover` 只返回候选 ID、来源和身份摘要，秘密留在主进程。`accounts.add` 与设备授权完成后的处理共用一个添加事务：按供应商身份去重、加密保存、建立订阅、加入持久队列；不等待远端查询成功。授权轮询只返回待完成/完成/过期和记录 ID。

外部凭据在每次查询前重新读取，并每 30 秒及唤醒时核对更新。来源更新只有在身份相同且本地代次未变时才持久化；变更取消旧查询。托管凭据由账号服务串行刷新，更新后先持久化再查询。凭据封装（含来源定位信息）整体保存在系统加密的 vault，不写入 SQLite 或备份。

自动订阅的身份、套餐、额度与来源由主进程保护，不接受编辑表单覆盖。删除最后一张关联卡片暂停该账号任务；短时撤销恢复更新。断开/删除只影响本应用。

## 整体完成标准

从已登录账号直接加入并自动展示权益；无登录时完成授权即加入；无需配置指标或点击读取。重启、Token 轮换、多账号切换与查询失败均保持正确身份和资料。真实账号逐服务对照，缺少账号/系统条件的项明确待验证，不只凭类型检查或模拟响应宣告接入完成。
