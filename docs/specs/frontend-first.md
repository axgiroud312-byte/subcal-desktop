## 1 这一阶段具体交付什么

交付真实桌面开发窗口，包含概览、订阅、日历、连接四个页面，以及统一的详情抽屉、新增编辑弹窗、设置、场景选择和最薄的托盘功能。所有主要按钮都有明确结果：执行本地操作、执行明确标注的模拟操作，或解释此阶段尚未接入。

可以新增、编辑、归档、删除、撤销删除演示空间内的订阅；修改后概览、详情和本地日历一起更新。退出并重开仍保留当前演示空间和界面偏好。提供无凭据的演示资料备份、导入预览与恢复。

此阶段不实施供应商查询、真实 OAuth、Key 保存、CLI 登录、SQLite/Drizzle 持久层、后台真实心跳、EventKit、CalDAV 或 Google 日历写入。不能因为按钮动画结束就提示真实连接或真实同步成功。也不需要 CI/CD、正式安装包、代码签名、Storybook 或重型测试体系。

Windows 是当前可执行的桌面验收环境；代码保持 macOS 兼容。没有 Mac 实机时如实标记“macOS 未实测”，不把这一点伪装成通过，也不因此停止其余前端工作。

## 2 采用的设计方向

以下保留第一版设计记录。本轮执行 [FE-011](../issues/FE-011.md)；涉及字号、卡片结构、账号展开、控件和样式实现的更新以[新视觉基础](../design/visual-foundation.md)为准。

### 2.1 信息层级

| 层级 | 显示内容 | 不放什么 |
| --- | --- | --- |
| 首屏行动区 | 今天或近期应核对的续费、到期、需要恢复的连接及可信的低额度提醒 | 无关的远期日期、技术堆栈、所有订阅的重复摘要 |
| 品牌卡片 | 产品、账号、核心额度或余额、下一续费/到期、字段各自的新鲜度 | 全量历史、所有诊断字段 |
| 右侧详情 | 全部窗口、收费安排、来源与人工锁定、共享关系、历史、提醒设置 | 无法证实的完整消费曲线 |
| 连接与诊断 | 支持字段、恢复动作、下一次模拟查询、结构化错误与脱敏示例 | 真实凭据输入和真实授权成功的表象 |

用户打开界面，先能回答“近期需要处理什么”，再能看出“还有多少额度”和“何时续费”。所有日期含义要通过文字区分，不能只靠图标和颜色。

### 2.2 导航与布局

保留 Magpie 的顶部导航方向：左侧 SubCal，自有应用标识；中部“概览 / 订阅 / 日历 / 连接”；右侧“新增订阅”和设置。默认不改成侧栏。

窗口目标 1280×820，导航约 56 高，主体内边距 20 至 24。默认卡片最小宽 340、间距 12，通常三列；紧凑模式最小宽 290，通常四列。最小窗口目标 960×640，常见情况下两列；一切按实际可用逻辑宽度计算，不写死列数。

实际工作区不足时，初始窗口及最小尺寸要服从屏幕可用区域，并允许内容滚动。Windows 的 150% 缩放不能靠“Chromium 会自动处理”来宣布验收，必须在实际逻辑尺寸检查。标题栏按钮安全区依据所用原生窗口模式处理，不假设固定安全区值适用于所有系统。

概览垂直顺序：

1. 常驻但克制的“前端预览 · 外部服务未连接”标记。
2. 最多三个近期行动项；其余进入“查看全部”。没有可行动项时显示中性的一行说明，不显示“所有真实连接正常”。
3. 筛选与排序栏，以及按币种分列的轻量支出说明。没有周期订阅时隐藏不适用的月费汇总。
4. 三类品牌卡片网格。固定顺序优先，刷新不重新排列，不夺取焦点。
5. 默认收起的“预览工具”入口，可展开场景与演示时钟。不要让一排调试按钮长期占据首屏注意力。

行动项优先级：已到计划日待确认、今明两天续费、其他七日内续费/到期、有效数据触发的低额度、需处理的连接/日历冲突、日期待补充。数据过时不能继续触发新的低额度结论。

## 3 三类卡片与统一详情

| 卡片类型 | 视觉重心 | 日期区 | 示例文案 |
| --- | --- | --- | --- |
| 窗口额度 | 独立的窗口名称、剩余大数字、进度条与重置时间 | 下一续费或到期单独一行 | “短窗口剩余 35% · 今天 21:00 重置（示例）；预计 11 月 3 日续费 · 手动记录” |
| API 钱包或 Key 预算 | 余额右对齐；充值、赠送等分项可展开；Key 预算单独命名 | 没有周期时显示“不适用” | “可用余额 ¥86.40（示例）”；“当前 Key 剩余预算 $23.75（示例）” |
| 手动会员 | 续费日期、剩余天数、价格与人工核对状态 | 主信息，不作为角落附注 | “2 天后计划续费 · $20/月（示例）；额度未自动读取” |

卡片顺序为产品标识、账号/套餐、核心指标、续费/到期、来源与更新时间。来源和时间按字段记录；不能用余额刚刚更新掩盖续费日期数周未核对。

同产品多账号可以在卡内分区，默认展示最多两个，更多可展开；每个账号有自己的日期和额度。同品牌不同产品分开。共用付款关系使用 billingGroupId，真正共享额度使用 quotaPoolId；两者互相独立。ChatGPT 会员与 Codex 可关联同一笔会员费用，但不能据此认定所有聊天与编程用量共享同一个额度池。

人民币与美元分列；钱包充值不计入固定周期月费；未知金额标明未计入数量。共享池重复展示时不重复加总。钱包低余额阈值按币种配置，未设置阈值时不从余额金额猜出剩余百分比。

详情统一采用右侧约 460 宽抽屉，较窄窗口可占据大部分可用宽度并独立滚动。分收费、额度、来源与历史、日历提醒四组，渐进展开。关闭后恢复原列表位置和触发元素的焦点。

新增/编辑采用约 560 宽弹窗，按基础与收费、可选额度记录、提醒三组呈现，可滚动。名称必填，未知日期允许留空。未保存修改需要清楚的保存或放弃选择，不使用抖动动画强迫关注。

## 4 状态与操作文案

存在三条独立维度：业务状态、数据可用性、数据新鲜度。演示来源是额外维度，不能代替其中任意一条。

| 状态 | 表达 |
| --- | --- |
| 明确零值 | “剩余 0%（示例）”或“余额 ¥0.00（示例）” |
| 未读取 | “尚未获取” |
| 当前适配能力不提供 | “当前读取方式未提供此项”，避免泛化成供应商永远没有接口 |
| 不适用 | “不适用 · 按量钱包” |
| 旧快照 | 保留数字，显示“3 小时前 · 已过时” |
| 已过重置点 | “预计已重置，尚待核实”，保留旧观察的时间，不补成 100% |
| 无上限示例 | “无限量（示例）”，不画假进度条 |
| 连接失败 | “需要重新连接（模拟）”，同时保留旧数据 |
| 模拟刷新 | 按钮与结果均标“模拟”，只更新脚本指定的字段 |
| 未实现能力 | 禁用按钮并解释“真实服务接入阶段实现”，不显示成功 Toast |

顶部的总预览标记不能替代各连接、额度、日历成功状态的局部说明。示例身份使用“个人示例账号”等名称，不凭空使用用户真实邮箱或伪装真实 Key 掩码。

“我已在官网关闭自动续费”只是用户主动修改本地记录；必须确认有效期依据，不能将下一扣费日自动当成已付有效期结束日。归档默认只停止本地跟踪、保留日程；是否清除模拟受管未来事件由用户单独选择。删除允许 8 秒撤销本次演示事务，但不能宣传成未来真实远端删除必然可原样撤销。

## 5 本地日历与外部同步预演

宽屏默认左侧约 65% 月历、右侧约 35% 选中日期的日程列表；同步设置由单独按钮展开，不长期挤占日程列表。宽度不足时切成月视图与列表切换，保留选中日期和筛选。

日期格最多两条事件，再显示“更多 N 项”。事件使用“续费 / 到期 / 试用结束 / 开始 / 额度重置”文字；预计日期有“预计”标签。没有确定扣款记录时不得把事件写作“已扣费”。重置默认关闭，启用后明确仅本地展示。

日期来自统一纯函数：月末锚点不漂移；年锚点处理闰年；日期型与时间型不混用；不按毫秒除 24 小时推算跨夏令时天数。同一逻辑日程改期保留 ID。开始日未知不生成事件，续费未知不按添加日期推算。

Google、macOS 系统日历、Windows iCloud CalDAV 是三种演示后端；界面分别说明实际 V1 路线。无需真实登录。选择后先看本次模拟新增、改期、移除的清单，再执行预演。

- Google 和 CalDAV 演示：模拟已排队 → 模拟已写入 → 模拟远端读回一致。
- EventKit 演示：模拟已排队 → 模拟写入系统日历 → 模拟本机读回一致；额外显示“iCloud 云端由系统同步，本预览未验证”。不能把本机读回写成远端已确认。
- 模拟冲突：比较两边日期，允许恢复本地计划、采纳为新的手动计划、解除管理并保留模拟外部事件。
- 模拟外部删除：保留抑制标记，普通刷新不能自动复活。
- .ics 如未实现，展示明确的后续能力说明；若实现导出必须确实生成文件，并标为静态导出。它不属于本阶段必须项，不能用 Toast 冒充文件已生成。

## 6 最小技术边界

建议结构是 src/main、src/preload、src/renderer，以及可复用的 src/shared 领域类型和纯规则。允许开发者按所选工具链微调，避免为了文件夹数量拆分项目。

采用 Electron、React 和 TypeScript。Renderer 关闭 Node 集成并隔离上下文；Preload 只暴露必要的窗口、托盘、安全链接或用户主动选择文件的能力。第三方登录页面不进入有本机权限的 Renderer。

组件包括 TopNav、PreviewBadge、BrandIcon、StatusBadge、FieldSource、QuotaMeter、MoneyValue、SubscriptionCard、DetailDrawer、SubscriptionForm、MonthGrid、AgendaList、SyncPreview、ConflictPanel。组件只有确实复用时才抽取，不建设独立组件展示网站。

所有页面通过异步 SubCalClient 访问数据，MockSubCalClient 是本阶段唯一实现，返回稳定 ID、revision、字段来源、新鲜度与结构化错误。组件禁止直接读 fixtures 或到处写 localStorage。

| 数据能力 | 本阶段行为 | 后续接口关系 |
| --- | --- | --- |
| 订阅列表、详情、创建、更新、归档、删除、撤销 | 演示空间内真实变更，revision 冲突可重现 | 对齐 PRD subscriptions 的业务含义 |
| 字段来源、共享关系、日程投影 | 使用共享类型和纯规则 | 未来可移至本地业务服务复用 |
| 连接与刷新 | 只对演示身份执行可控状态转换 | 对应 connections 与 collections，暂不实现真实认证 |
| 日历预览、阶段、冲突处理 | 更新模拟绑定及事件列表 | 对应 calendars；区分本机与远端确认 |
| 备份、导入预览、提交 | 只处理演示元数据，不含秘密 | 对应 data；导入后模拟目标暂停 |
| 场景和演示时钟 | 单独的 PreviewController | 开发工具，不冒充未来正式 IPC 方法 |

“对齐业务含义”不意味着 Gemini 示例中的回调函数可以原样跨 IPC 序列化。事件订阅或轮询由实现时明确协议，不将函数作为跨进程参数。

演示快照可持久化在单一、带 schemaVersion 的 localStorage 命名空间；数据量保持小规模。存储访问只在服务层，包含解析失败恢复。记录是测试空间的演示编辑结果，不宣称生产资料已获得 SQLite 或系统密钥保护。

使用可注入的 DemoClock，默认示例时间固定为 2026-10-20 09:00 Asia/Shanghai，在预览工具中显示。日期边界场景使用自己的时钟；不要用随机数或依赖当天日期来碰运气触发状态。重置和切换会覆盖编辑时先说明范围；可按场景独立保存，避免悄悄丢失输入。

## 7 必须可切换的示例场景

场景控制在 FE-002 就具备，后续页面陆续消费，不等到最后才补模拟数据。

| 场景 ID | 必须覆盖的结果 |
| --- | --- |
| empty_first_run | 零条记录，能添加第一项或主动载入示例 |
| normal_mixed | 三类卡、不同币种、不同来源；至少六条典型记录 |
| multi_account_shared | 多账号折叠、共享付款关系与独立额度池、疑似钱包不重复计数 |
| unknown_and_na | 未填日期、未提供字段、不适用各不相同 |
| zero_vs_unfetched | 明确零值与尚未取得不混同 |
| stale_and_past_reset | 旧值保留，重置已过也不自动恢复满额 |
| partial_success | 仅成功字段更新时间，失败字段不“刚刚更新” |
| auth_and_locked_fields | 失效连接与人工锁定冲突，可恢复且不静默覆盖 |
| rate_limited | 重复刷新合并，可见下一允许时间 |
| offline_recovery | 能离线看与编辑，恢复只模拟补查一次 |
| date_boundaries | 月末、闰年、跨时区/夏令时、已到计划日待确认 |
| calendar_conflicts | 不同后端确认边界、目标失效、外部改期/删除及恢复 |

错误示例不需要真实服务来制造。历史只有模拟服务实际产生的编辑与观察记录，所有示例观察均带演示来源。

## 8 视觉规格和对 Gemini 建议的校正

采纳顶部四导航、行动区、轻量汇总、三类品牌卡、右侧详情抽屉、双栏月历和可切换模拟场景。主要参考 [本地 Magpie 参考图](../references/magpie-usage-reference.png)；原始链接和代码版本见 PRD 第 04 章。

卡片圆角 10，内边距 14 至 16，间距 12；正文 13 至 14，辅助信息至少 12，核心数值 20 至 24，开启等宽数字。使用真实且许可可核对的品牌素材，缺少时用文字后备。品牌素材和第三方许可随本地资源记录，不从任意 URL 即时拉图标。

以下校正已经成为执行要求：

1. 原建议混用了“共用订阅账期”和“共享额度池”，按本规格第 3 节拆成独立关系。
2. 原建议部分模拟成功示例缺少局部“模拟”字样；统一按第 4、5 节处理，EventKit 也不获得假的云端确认。
3. 原建议将深色辅助文字 #7E7E87 放在 #222226 上并声称达到 4.5:1，实际按颜色计算约 3.94:1；改为如 #A1A1AA，约 6.18:1。白字配 #6366F1 约 4.47:1，普通小字按钮改用对比足够的组合，例如白字配 #4F46E5 约 6.29:1。最终仍以实际文字、字号和背景核对。
4. 抽屉统一采用约 460 宽，解决原文 440 与 460 两种尺寸冲突。小窗口按可用区域调整。
5. 默认调试入口收起，不将完整状态按钮条长期放在主要阅读路径。
6. 取消自动续费不推断 paid-through 日期；归档不默认删除外部事件；预览阶段所有删除范围都明确限于演示空间。
7. 原始模型给出的接口代码是建议，不直接视为与 PRD IPC 完全同构；按第 6 节分离预览控制与产品数据合同。

## 9 任务与完成边界

第一轮 FE-001 至 FE-010 已交付功能基线，视觉未通过。当前执行 [任务索引](../issues/README.md) 中 FE-011 至 FE-018：先统一 Token 和组件，再迁移页面与整体验证。

只做必要校验：类型检查、日期/计量/合并等高风险纯规则的小范围测试、真实 Electron 主流程、深浅色与窄窗口检查。不设 100% 覆盖率门槛，不为每个低风险按钮编写重复测试。

前端完成的可观察结果：能打开桌面窗口，切换场景，新增和编辑记录，观察卡片与日历联动，演示错误恢复与同步冲突，重开后保留数据，并找到明确的启动命令。当前阶段不需要真实账号；未来真实服务接入仍须满足 PRD 的验收门槛。

Issue 的“开发完成”“功能检查”“视觉核对”“用户已验收”分别记录；用户否定后标 needs_revision，写明反馈和承接任务。新版本完成实际检查后待用户验收，不能自动标 accepted。
