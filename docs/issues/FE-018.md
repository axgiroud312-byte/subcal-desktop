# FE-018 用真实桌面证据完成视觉重做验收与交付

父任务：[FE-011](FE-011.md)。前置：[FE-014](FE-014.md)、[FE-015](FE-015.md)、[FE-016](FE-016.md)、[FE-017](FE-017.md)；传递覆盖 FE-012、FE-013。依据：[视觉基础第 5 节](../design/visual-foundation.md)。

## 目标与范围

整合各页面，清理迁移完成后不再使用的重复样式和兼容映射，检查视觉与业务交互，留下可实际打开的桌面窗口和用户可以直接核对的证据。

## 视觉检查

- 按角色检查颜色、字重、字号、间距、圆角、阴影、焦点和禁用态；页面内新增硬编码视觉值必须迁入 Token 或记录明确的业务例外。
- 对照共同设计核对实际组件采用：Mira / Base UI 控件、Motion 展开过渡、dnd-kit 卡片排序、Recharts 图表示例和 Lucide 图标；记录使用文件及操作结果，排除仅安装未使用的交付。
- 四页及主要浮层分别查看深浅色；检查正常、多账号、未知/零、过时、失败、空状态，确认主要信息顺序与渐进展开符合设计。
- 实测 1280×820、960×640 和 Windows 150% 缩放；记录实际逻辑尺寸与 DPI，不用浏览器截图替代 Electron 交付。
- 代表截图建议八张：四个页面各一张、概览另一主题一张、窄窗口详情/表单/月历各一张。其余状态以检查记录说明，发现具体问题再补必要截图。
- 保存到 `docs/evidence/visual-v2/`，说明截图场景、主题、尺寸以及与旧版相比解决的具体问题；旧截图作为历史基线保留。

## 功能回归与交付

1. 运行 `npm run typecheck`、`npm run test:rules`、`npm run test:desktop`。选择器随新语义结构调整，但不能删断言来掩盖失效。无新故障不重复全量运行。
2. 用独立资料目录核对新增、编辑、详情、删除撤销、重启恢复、场景切换、排序、连接恢复、三后端同步预演、备份恢复及托盘入口。
3. 特别复查 Sheet/Dialog 焦点返回、嵌套菜单 Escape、未保存保护、Portal 主题、旧数据可见性和模拟结果文案。
4. 更新 README、素材/组件实际来源、各 Issue 状态与证据链接。状态分为功能检查结果、视觉核对结果、用户验收结果。
5. 实施检查完成后父任务可标 verified / 待用户验收；只有用户明确接受才能 accepted。若用户否定视觉，写明原因并回到 needs_revision。
