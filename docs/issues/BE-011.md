# BE-011 账号自动发现与登录接入，自动生成订阅及更新余额/额度

> 执行入口已被 [BE-012](BE-012.md) 接替：用户明确要求优先直接移植 Magpie / CC Switch 代码。本文的候选路径描述不再作为开发者重新设计接入方式的依据，术语和正确性规则继续复用。

状态：ready，功能尚未实施；用户验收 pending。远端任务：[GitHub #3](https://github.com/axgiroud312-byte/subcal-desktop/issues/3)。与旧总目标 #1、PR #2 相关，本任务单独追踪；不以旧 PR 的检查结果代替本任务验收。

## 问题与目标

当前入口仍把“读取、探测、绑定”暴露给用户，且主要依赖已安装的官方客户端运行时。用户要求像 Magpie / CC Switch：复用已有登录，或登录/填 Key 后自动生成订阅和权益卡片，持续更新。

依据：[术语](https://github.com/axgiroud312-byte/subcal-desktop/blob/feat/real-backend/GLOSSARY.md)、[当前规格](https://github.com/axgiroud312-byte/subcal-desktop/blob/feat/real-backend/docs/specs/account-access.md)、[源码核对及固定提交链接](https://github.com/axgiroud312-byte/subcal-desktop/blob/feat/real-backend/docs/references/account-access-source-review.md)。实现顺序按下面工作包推进，公共账号身份与凭据合同先统一。

## 工作包与局部设计

### A. 账号及凭据来源合同
- 建模服务、账号主体、工作区、来源引用、外部登录/托管登录、凭据代次；与旧 connections/subscriptions 兼容迁移。
- 发现接口返回候选 ID、身份摘要、来源、是否已添加和可用状态；凭据留主进程。
- 明确 Windows 实际文件/系统凭据库支持清单与自定义目录规则，不把“读不了”当“没有账号”。

### B. 自动发现与登录（依赖 A）
- Codex：读取实际配置存储（auth.json/适用系统凭据库），识别 ChatGPT 登录与 API Key 模式；支持应用内设备码授权。
- Claude Code：发现配置目录登录/适用钥匙串；接入策略比较 CC Switch OAuth 查询和 Magpie CLI /usage，记录所选版本与实测依据，不静默退回手工指标。
- Copilot：区分编辑器 apps.json/hosts.json 与 CLI config.json+系统凭据库；支持 GitHub 设备码授权，不能混用两类 Token 交换路径。
- API 服务：从已支持的供应商配置导入 Key 或填 Key；同账号去重并保留来源。
- 外部登录跟随凭据更新；托管登录串行刷新、原子保存、拒绝旧代次覆盖。删除账号不影响原客户端登录。

### C. 权益自动查询（依赖 A/B 的有效凭据）
- Codex：`GET https://chatgpt.com/backend-api/wham/usage`，Bearer 与账号/工作区标识；按实际返回归一化全部窗口。
- Claude：候选 `GET https://api.anthropic.com/api/oauth/usage`（Bearer + 对应 beta 头）或后台 CLI /usage，按实测选定并记录。
- Copilot：`GET https://api.github.com/copilot_internal/user`，匹配凭据来源的请求头，遍历返回额度而不是硬编码套餐。
- DeepSeek：`GET https://api.deepseek.com/user/balance`。
- Kimi API 国内：`GET https://api.moonshot.cn/v1/users/me/balance`，验证业务状态；不当作 Kimi Code。
- OpenRouter：`GET https://openrouter.ai/api/v1/credits` 为账户余额；`/api/v1/key` 单独展示 Key 预算，用权限错误表达不可读，不做语义替换。
- 接口、认证过程、响应字段和来源版本详见源码核对，不把内部端点说成公开 API。没有真实账号时仅完成实现/结构测试，保留待验证。

### D. 无感加入及后台更新（依赖 A—C）
- 选择已发现账号，或授权/Key 成功后自动创建资料并启动查询；幂等重复操作只产生一条关联记录。
- 删除额外“读取/探测/确认字段/启用心跳”操作，查询失败保留账号卡片和恢复入口。
- 凭据变化通知与定时校验结合；远端轮询缓存、退避、唤醒合并复用现有调度。无需代理聊天流量。
- 套餐、指标名称/单位/重置自动生成；编辑账单保留已有观察，未知账单不猜测。

## 可观察验收

- [ ] 已登录 Codex/Claude/Copilot 的支持来源在添加页自动出现；无需复制 Token、配置指标或点击读取。
- [ ] 没有已有登录时，完成受支持授权即可加入；API 服务取得 Key 后自动加入并查询。
- [ ] Windows 自定义目录及文件型登录实测；系统凭据库与 macOS 支持分别记录结果，不能以其他平台通过代替。
- [ ] 同邮箱不同工作区不混淆；同账号重复添加不重复；切换后迟到响应不污染新账号。
- [ ] Token 更新、原客户端刷新、失效重登和重启后均保持正确账号；不擅自改写/删除来源凭据。
- [ ] 六类服务逐项记录真实接口/官方视图对照；没有账号明确标待验证，不能用测试样例宣称完成。
- [ ] OpenRouter 余额与 Key 预算不混用，Kimi API 与 Code 不混用；缺字段和查询失败不归零。
- [ ] 新增账号后查询失败仍保留订阅；编辑收费信息不修改额度来源、观察时间或重置时间。
- [ ] Renderer、日志、普通备份与诊断无明文凭据；自动查询没有创建对话或消耗积分。
- [ ] 真实 Electron 从发现/登录到卡片的一条完整流程通过，并记录重启与后台更新结果。

## 进度与交付要求

术语/规格与参考源码核对已完成；功能实现未开始。凭据来源平台适配、Claude 查询策略和实际 Token 权限是实施时必须验证的项目。最终提交关联 PR，分别记录开发完成、验证完成、用户验收；未经用户接受不标 accepted。
