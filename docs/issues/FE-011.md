# FE-011 交付视觉统一、主次清楚的 SubCal 桌面前端

## 目标与范围

用户否定第一版视觉后提出新一轮要求：统一颜色、字体、字重、间距、圆角等 Design Tokens，采用成熟现代前端组件，并落实 Magpie 的信息层级。以现有可操作桌面预览为基线完成视觉重做。

共同依据：[视觉基础与组件约定](../design/visual-foundation.md)。业务依据：[前端规格](../specs/frontend-first.md)。前序交付：[FE-000](FE-000.md)、[FE-010](FE-010.md)；其已有功能检查不代表视觉已经通过。

## 实施约定

- shadcn/ui 选择 Mira 紧凑风格的 Base UI 版本，Tailwind CSS 4 统一 Token，Lucide 统一应用图标；Motion、dnd-kit、Recharts 3 按共同设计的使用点实际接入。每项记录真实导入、组件使用位置和可操作检查结果。
- 页面数据继续通过统一异步 MockSubCalClient；十二场景、持久化、日期/金额规则、共享付款与额度池区别是回归基线。
- 本批范围是视觉与既有交互整合，真实外部采集和日历写入仍按原产品阶段执行；不扩大为无数据依据的统计系统。
- 如采用并行实施：基础负责人维护 Token、基础 UI、公共 CSS 和依赖；页面负责人通过公共接口消费。`App.tsx`、`components/ui.tsx`、`calendar-connections.css` 的共享修改先约定责任并由整合者收敛。
- 沿用用户的模型用量偏好：Gemini 4 Argon Contributor 主要承担前端，Kimi K3 仅在独立小任务有收益时少量使用；避免重复全仓调研、重复全量验证。实施者在领取时记录实际负责人，不预先声称已委派。

## 验收

- 四页及详情、编辑、同步、设置使用同一套 Token 和控件；字重以 400/500/600 分工，辅助说明不抢主数字。
- 额度行没有重复的内层卡片框，品牌清楚，主要金额/日期与可操作异常易于定位。
- 深浅色、窄窗口、150% 缩放、键盘与 Portal 弹层可用，模拟身份与关键字段状态清晰。
- FE-018 留下真实窗口截图、视觉核对结论、必要功能回归与启动入口。
- 本父任务需用户明确接受后才标记 accepted。
