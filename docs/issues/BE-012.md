## 明确的接入路线与移植清单

固定版本源码根目录：
[Magpie](https://github.com/yetone/magpie/tree/ba319a7587923fc7a4ea3859658244d591261a59)；[CC Switch](https://github.com/farion1231/cc-switch/tree/c776fd0ebfe35d769b5909b86bdfa1ccdf089988)。下面路径均相对该根目录。

### 1. Codex：读取登录凭据或应用内授权，直接查权益

- 移植 Magpie `internal/provider/account.go` 的 `codexAccount` / `readCodexLogin` 调用链及目录解析；读取实际 Codex 配置目录的 auth.json 或对应系统凭据存储，尊重自定义目录与存储模式。
- 移植 CC Switch `src-tauri/src/proxy/providers/codex_oauth_auth.rs` 的设备码授权、账号管理、刷新锁、凭据代次和轮换冲突处理。
- 直接使用 Access Token 和 ChatGPT-Account-Id 请求 `GET https://chatgpt.com/backend-api/wham/usage`；移植 `src-tauri/src/services/subscription.rs` 和 Magpie `internal/provider/subscription_usage.go` 对套餐、窗口与积分的归一化。
- 已取得有效凭据时，不再强制安装/启动 Codex App Server。身份按账号/工作区区分，不能以邮箱单独合并。

### 2. Claude Code：本机凭据接入，直接查询为主

- 移植 CC Switch `src-tauri/src/services/subscription.rs` 的凭据读取与解析：Claude 配置目录 `.credentials.json`、macOS 对应钥匙串、两种 OAuth 字段结构。
- 主路径固定为 `GET https://api.anthropic.com/api/oauth/usage`，使用对应 OAuth Token 和请求头，移植实际额度解析和错误处理。
- Magpie `internal/provider/claude_usage_cli.go` 的 `/usage` 解析仅作为明确记录原因的兼容后备，不作为用户必须启动 CLI 或复制用量文本的主流程；不把普通推理调用误当查询命令。
- 外部登录更新后自动重新取得凭据；缺少登录时给出具体登录入口，不降级成让用户手填额度。

### 3. Copilot：区分已有登录来源，支持设备码登录

- 移植 Magpie `internal/provider/account.go`、`copilot_cli.go` 的编辑器 apps.json/hosts.json 与 CLI config.json/系统凭据库读取；尊重 COPILOT_HOME。
- 移植 CC Switch `src-tauri/src/proxy/providers/copilot_auth.rs` 的 GitHub 设备码授权与账号管理。
- 直接查询 `GET https://api.github.com/copilot_internal/user`，请求头匹配凭据来源，解析套餐、实际 quota_snapshots 和重置时间。
- CLI Token 和编辑器 Token 的交换路径不得混用；查询权益不要求额外安装官方 SDK 运行时。

### 4. API 钱包：导入已有 Key，自动匹配查询方式

- 复用 Magpie `internal/gui/assets/app.js` 的配置发现/导入流程语义，并沿其 `importapps` 后端调用链移植实际支持来源。已支持来源里的 Key 自动读取，前端只展示来源及掩码；新增 Key 是缺少来源时的入口。
- 复用 Magpie `internal/provider/balance.go`、CC Switch `src-tauri/src/services/balance.rs` 的对应请求与解析：
  - DeepSeek：`GET https://api.deepseek.com/user/balance`。
  - Kimi API 国内：`GET https://api.moonshot.cn/v1/users/me/balance`，检查业务成功状态，不用于 Kimi Code。
  - OpenRouter 账户余额：`GET https://openrouter.ai/api/v1/credits`；Key 预算/用量用 `/api/v1/key` 单独展示。权限不足明确表示，不互相替代。
- 真实配置格式与平台路径逐项记录支持范围，不宣称所有第三方配置均可导入。

## 必须移植和整合的行为

1. 账号发现后台完成，添加页直接呈现已有账号及来源；不是先选服务后再要求“读取账号”。
2. 用户加入账号或授权/Key 保存成功后立即幂等创建记录并查询；暂时查询失败保留账号与旧数据，不要求重走添加流程。
3. 外部登录跟随和本应用托管登录分别管理。移植刷新代次/锁逻辑，不简单复制 Refresh Token 后让两个应用无协调刷新；不得把旧凭据覆盖到原客户端。
4. 本地凭据变化触发重识别，远端权益由后台定时查询、缓存、退避和唤醒合并更新。“监听”不等于存在供应商推送接口；无需代理用户聊天流量。
5. 新增、重启、重登和多账号切换使用同一套账号身份与来源规则。移除本应用账号不注销原客户端、不删除其配置。
6. 原有 SQLite、safeStorage、任务调度和独立采集进程继续复用；来源敏感数据不得进入 Renderer、普通备份、日志或诊断。
7. 客户端内部接口记录为内部接口，保留版本和错误恢复。不得以旧文档的“仅官方公开 API”限制偷偷换回现有客户端查询向导。

## 验收：以用户实际操作为准

- [ ] 有现成登录时，打开添加页就能看到账号；选择加入后自动出现实际套餐/额度，不操作读取/探测/绑定。
- [ ] Codex/Copilot 在有效凭据可读时，查询路径不依赖启动官方客户端/SDK 运行时；缺登录时完成授权后自动加入。
- [ ] Claude 的已支持凭据来源直接得到真实额度；兼容后备单独记录触发原因和版本，不把后备冒充主路径完成。
- [ ] 已支持第三方配置里的 Key 不需要重复输入；首次新增 Key 后自动生成余额卡片。
- [ ] 重复添加不重复记录；同邮箱不同工作区不串号；旧凭据和迟到结果不能覆盖新代次。
- [ ] 原客户端刷新、退出重启、Token 失效和重新登录均实测；不破坏其他应用的登录状态。
- [ ] Windows 文件型与系统凭据库存储分别验收，macOS 另记结果；读取失败不伪称没有账号。
- [ ] 套餐/额度窗口全部由实际响应生成；余额与预算不混淆，失败不归零，不猜账单日期。
- [ ] 逐服务记录真实账号对照、请求方式、返回字段及 UI 结果；无账号的项标待验证，不能拿 mock 或构建成功替代。
