# FE-020 从账号连接自动加入订阅

状态：implemented，真实 Windows 桌面已检查；用户验收 pending。补充 Issue #1 / PR #2。

用户指出新增订阅表单不应要求配置指标名称、单位、剩余额度或 availability。根因：主入口仍走旧手动表单，真实适配器已有的自动建档未成为默认路径。

参考已实际阅读的 yetone/magpie 源码：`internal/gui/assets/app.js` 的 discoverLocalProviders/openImportApps 和添加 provider 入口；`internal/provider/subscription_usage.go` 的 SubscriptionQuota/QuotaWindow；`internal/provider/codex_limits.go` 的窗口合并。Magpie 先获取账号/Key，再归一化厂商报告的额度窗口；配置导入也由服务端读取、用户确认。其私有接口/认证文件实现不复制，SubCal 仍走官方只读途径。

实现：新增订阅先选择支持服务；本机客户端一键读取，HTTP 服务只填 Key；读取后确认自动加入订阅并启用更新。手动记录另设明确入口；删除手动指标编辑和内部状态选择，不凭目录填套餐价格或额度桶；编辑账单保留已采集指标。

验收：从全局新增到 Codex 读取/自动加入无需配置指标；HTTP 只要求 Key；手动新建无预造指标；编辑不篡改采集来源/时间；类型检查和真实 Electron 流程通过。

结果：类型检查及六组桌面检查通过；实际 Codex 从全局新增 → 选择服务 → 读取账号 → 确认添加 → 自动卡片流程通过，随后编辑收费信息，全部采集指标、来源及时间保持一致。见 `docs/design/account-onboarding.md`、`docs/evidence/backend-v1/add-service.png` 及更新后的真实桌面报告。
