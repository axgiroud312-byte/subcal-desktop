# FE-003 在概览看懂近期行动与三类品牌订阅卡

父任务：[FE-000](FE-000.md)。前置：[FE-002](FE-002.md)。依据：[前端规格第 2 至 4、8 节](../specs/frontend-first.md)、[Gemini 方案第三和第四部分](../design/gemini-frontend-proposal.md)。

## 目标与范围

完成第一屏可供用户直接评价的视觉与交互：近期行动区、轻量汇总、筛选排序、三类卡片、多账号折叠和手动排列。

正常示例至少显示 Codex 窗口卡、Copilot 无限量或窗口卡、DeepSeek 钱包卡、Kimi API 钱包卡、OpenRouter Key 预算卡及手动会员卡。数据含义依据前端规格，不把这些示例当作实际读取结果。

支持全部、近期续费、低额度、需处理、手动记录的筛选；默认/紧凑密度、剩余/已用切换、品牌与日期排序、拖动和键盘调整顺序。刷新中保留现有内容，用户位置与卡片顺序稳定。

详情点击通过稳定的 onOpenSubscription(id) 接口交给后续 FE-004；本任务的焦点和按钮边界先做好，不能在整卡嵌套不可操作的按钮。

## 验收

- 在真实窗口看见 Magpie 方向的图标、右对齐数字、留白和三类卡片；默认三列，宽度变化后自适应。
- 续费与重置分行，钱包没有假月度周期，手动会员以续费安排为重心。
- 多币种分列；钱包不进固定月费；同一付费关系只算一次；未知价格的遗漏数量可见。
- 同产品多账号各有日期与额度；同品牌不同产品分开；多账号展开不会移动当前点击目标。
- 已过时的数据不制造新的低额度行动项；无行动项时没有虚假的“真实连接一切正常”。
- 切换场景能看见零、未知、过时、无限量和部分更新等差异。

## 当前进展

用户已否定第一版视觉；本任务的功能检查保留，视觉由 [FE-014](FE-014.md) 按[新视觉基础](../design/visual-foundation.md)重做。下文描述第一轮实现，不作为新批次的视觉验收结论。

实施：三类卡片、最多三个近期行动项、筛选与排序、手动拖动/Alt+左右排序、独立月费与未来 30 天预计支出、多账号展开、额度方向与阅读密度、字段各自的新鲜度。钱包分项默认收起，预览工具默认收起。

已验证：真实 Electron 中多账号展开、排序重启保留、零值/未知/过时文案、部分成功更新；规则检查验证共用付款去重和多币种分列。150% 系统缩放下浅色/深色与窄窗口已查看，截图见 FE-010。负责人：Gemini 4 Argon Contributor 实现，主 Agent 整合。分支/PR：无。用户反馈：第一版视觉不接受。
