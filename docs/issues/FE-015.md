# FE-015 用一致的列表、详情与编辑组件完成订阅操作

父任务：[FE-011](FE-011.md)。前置：[FE-012](FE-012.md)。依据：[视觉基础第 4.3 节](../design/visual-foundation.md)。

## 目标与范围

迁移 `SubscriptionsPage.tsx`、`DetailDrawer.tsx`、`SubscriptionForm.tsx`。交付同一订阅从列表进入详情、编辑并返回的统一视觉与键盘体验。

## 实施要点

- 列表使用统一 Table、Input、Select、DropdownMenu；主要名称、金额、日期、状态分清层级，行内低频动作收拢。
- 详情用 Sheet 组织收费、额度、来源历史、日历提醒；解释使用 description / Accordion，主要金额和日期不藏在折叠项里。
- 编辑用 Dialog 与统一 Field；复用现有校验、来源和 revision 冲突处理，不引入第二套收费/日期校验。
- 未保存修改通过受控 AlertDialog 处理，连续 Escape 不绕过选择；嵌套 Select/Popover 的 Escape 优先关闭自身。
- 保存、归档、删除、撤销、恢复等沿用现有服务语义，操作反馈使用统一入口。

## 验收方法

- 从列表和概览分别进入同一订阅，内容一致；保存后列表、详情与日历更新，未改字段的来源时间不被重写。
- 关闭详情回到触发元素及原滚动位置；Tab 不逃出模态框，关闭菜单不会误关整个表单。
- 连续 Escape、取消放弃、表单错误、revision 冲突均能恢复操作，不丢未保存值。
- 960×640 中抽屉和表单可滚动，标题、保存/取消可达，金额/日期不截断；两主题 Portal 正确。
- 使用现有管理流程做针对性检查并记录代表结果。
