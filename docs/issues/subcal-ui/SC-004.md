# SC-004 在新账号页完成发现登录和真实权益状态展示

跟踪：[GitHub #47](https://github.com/axgiroud312-byte/subcal-desktop/issues/47)；父目标 [#43](https://github.com/axgiroud312-byte/subcal-desktop/issues/43)；前置 [#45](https://github.com/axgiroud312-byte/subcal-desktop/issues/45)。

## 目标与范围

父目标 SC-000；复用既有 #37 的 Magpie 订阅展示和账号入口。使用原型账号管理布局接入现有生产能力，保留按服务/地区/组织区分账号；任何订阅卡片/详情继续旧展示。本项不重复开发所有供应商适配器。

## 局部设计

复用 ConnectionsPage、AddSubscription、SERVICE_ACCESS/登录能力目录以及 discoverAccounts/addAccount/startAccountLogin/pollAccountLogin/submitAccountLogin/cancelAccountLogin/refresh/pause/disconnect。原型统一“未连接”和仅官网跳转改为真实流程。

显示已添加、更新中、部分成功、需要重新登录、过时、限流/离线及缺组件/配置；来源、更新时间和失败恢复放在对应账号附近。只有有实现的登录方式可启用，供应商未给字段保持未知；官方 CLI 登录仍由应用后台编排。

沿用受保护凭据流程；Key 仅当前授权表单瞬态输入，保存后清除，不进入页面持久草稿/日志/普通备份。关闭或切换服务取消旧授权并隔离旧结果。使用现有 Card/Badge/Dialog/Field/Select/Button/Collapsible + Lucide，统一绿色 Token。

依据 `docs/specs/account-access.md`、`docs/specs/full-service-entitlements.md` 和 `docs/design/subcal-green.md`。接口存在不等于真实账号验证通过。

## 可观察验收

在隔离 Electron 资料库加入已有账号或发起登录；完成后自动建订阅且更新，不多一次“读取/绑定”。查询失败仍保留账号，可重试/重登；重启后身份不丢。合成流程覆盖取消、超时、局部失败、多账号和旧响应；可用真实账号单独对照。

已有 Codex/Grok Build 成功证据只作基线；本次无凭据或 Google OAuth 未配置的服务记录具体阻碍，页面不能造成功状态。运行受影响 account-access/login/renderer 测试，不要求把全服务验收 #38 完成作为新界面前提。

## 依赖与进展

前置 SC-002。业务适配器和真实账号覆盖继续关联原服务 Issue；与 SC-003 共用添加/详情入口。状态 implemented：账号页已接入新外壳，真实发现/登录/Key 入口保留；真实账号逐一覆盖仍归 #38，用户验收 pending。
