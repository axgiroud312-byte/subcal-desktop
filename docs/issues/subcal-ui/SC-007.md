# SC-007 在本地日历正确显示付款安排并按设置提醒

跟踪：[GitHub #50](https://github.com/axgiroud312-byte/subcal-desktop/issues/50)；父目标 [#43](https://github.com/axgiroud312-byte/subcal-desktop/issues/43)；前置 [#45](https://github.com/axgiroud312-byte/subcal-desktop/issues/45)、[#48](https://github.com/axgiroud312-byte/subcal-desktop/issues/48)。

## 目标与范围

父目标 SC-000。迁移月历＋侧栏、日程、日期详情、类型筛选和付款入口；补季度周期与可配置提醒。来源语义仍由账号/权益规格决定。

## 局部设计

复用 CalendarPage、events/calendars.events/projectEvents、anchoredDate/dateInZone 和 NotificationService。业务月历继续 React 网格，Button/Tabs/Select/Sheet 复用 base-mira；不额外引入全功能日历库。

续费、会员到期、试用、额度重置分别显示，既有 start 可在筛选中保留。未知不造日期；日精度无假时刻，instant 按时区投影；Token 到期不进入会员事件。结合 SC-005 稳定发生项/付款，显示已记录 N 笔及真实日期，不能一笔补付就冒充付清；删除付款更新标记，顺延仍可追溯原付款。

季度扩展 Cycle/schema/anchoredDate/月均折算/表单/备份读取，按三个日历月推进；保留 monthly/yearly/days/once/irregular/none。新旧计划期次/身份迁移不能串账。

新增全局 reminderLeadDays 和订阅可空覆盖值（拟命名），默认 3 天、UI 可选 1/3/7/14；保留 reminder 通道、静音、勿扰、托盘和持久 dedupe。跨午夜/DST 按民用日期算提前范围，不用毫秒/24h；配置变更或重启不爆发重复通知。提醒中心和系统通知复用同一候选规则，提醒状态与 OS 实际送达区分。

Google/iCloud/EventKit 外部同步沿当前 NOT_IMPLEMENTED 状态呈现；本地月历完整可用，不用 Mock 同步成功充当真实集成。

## 可观察验收

月历/日程/日期侧栏一致，记账后可看关联记录，返回保留月份/筛选。月末 1/31→2 月末→3/31、闰年年周期、季度 1/31→4/30→7/31、日期/时刻和 DST 有规则证据。自动缺日期仍未知。

设置提前 7 天后仅匹配范围，单项覆盖和全局关闭生效；勿扰跨午夜、重启去重可检查。实际 OS 通知测试能否送达单独记录，不把 mock port 通过当作系统成功。运行受影响 rules/backend 和 Electron 日历操作。

## 依赖与进展

前置 SC-002、SC-005；完成后提供提醒配置字段给 SC-008。本项拥有周期/提醒规则及相应最小设置控件，最终设置布局由 SC-008 整合。状态 implemented：付款标记/已付计划追溯、季度周期（三个日历月）、全局与单项提前天数已接通；external 通道仍未接入，用户验收 pending。
