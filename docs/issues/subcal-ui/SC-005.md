# SC-005 持久保存逐笔付款预算并安全迁移备份

跟踪：[GitHub #48](https://github.com/axgiroud312-byte/subcal-desktop/issues/48)；父目标 [#43](https://github.com/axgiroud312-byte/subcal-desktop/issues/43)。无前置任务。

## 目标与范围

父目标 SC-000。本项交付新消费页面所需真实数据能力，不是给 price 改名。唯一业务定义在 `docs/domain/spending.md`，整体接线见 `docs/specs/subcal-production-ui.md`。

## 局部设计

先复查 database.ts 的 schedule_rules/billing_occurrences、record_json 与设置存储。当前 occurrences 只有结构、没有实付字段，且删除订阅会级联删除计划。新增独立付款表；PaymentRecord 和付款查询/创建/修改/删除/撤销为拟新增合同，贯穿 shared/types/schema/bridge、主进程 service/database、IpcSubCalClient 和显式预览 Client。

付款保存稳定 ID/revision、金额十进制字符串/币种、实际支付日、订阅/账单主体、名称/分类快照、来源/时间、可选稳定计划关联与日期快照。新增本地分类与 workspaceName/statisticsCurrency/monthlyBudgets 等偏好（最终命名以实现同步）；自动订阅分类作为独立用户元数据，不放开来源字段。预算缺省未设置，与零预算区分。

复用百万分之一 BigInt、幂等请求和版本检查。新增请求重试复用 key，后端原子落账＋保存结果；同一期真实分笔/补付允许独立记录。不得用 renewal:0 作为永久关联；稳定发生项身份能跨顺延/改期/计划变更保持原付款归属。

记录付款＋可选手动顺延在一个事务核对付款和订阅版本；只准手动计划，按原锚点，重复同一期不会再次推进。短时撤销只回滚本次仍未被后续修改的版本。之后单独删除/改账不回退计划；删除订阅不级联删付款。

迁移先走现有 SQLite 一致性备份；schema/JSON 备份在最新版本上递增。导出/导入覆盖账本、计划关联、预算/分类和新偏好；读取旧 v1/v2，旧资料不虚构历史付款。旧备份整体替换会影响账本时，预览明确删除数量并沿用现有确认流程。preview 绑定 hash/revision，导入事务失败不半写。凭据仍不进入备份。

## 可观察验收

真实 IPC 创建 USD 18 付款，重复同 key 仍一笔；另记 USD 2 补付总额为 USD 20。过期 revision 修改失败，原记录不变。6 位小数、大数汇总、不同币种和共享付款/共享额度分别测试。自动订阅请求顺延必须拒绝且不半写；手动月末顺延/重复/撤销正确。

重启恢复付款和预算；归档/删除订阅后历史账仍在；导出并导入独立资料库数据一致；旧 v1/v2、损坏导入、导入前资料变化均有正确结果。复用 backend/rules 测试结构并补真正的持久边界测试；typecheck 通过。
