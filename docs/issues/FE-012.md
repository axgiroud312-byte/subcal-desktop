# FE-012 让颜色、字重、间距和基础控件拥有统一来源

父任务：[FE-011](FE-011.md)。依据：[视觉基础第 2、3 节](../design/visual-foundation.md)、[组件接入说明](../design/component-adoption.md)。

## 目标与交付

建立可被所有页面实际使用的 Design Tokens，接入 shadcn/ui 的 Mira 紧凑风格（Base UI 版本）、Tailwind CSS 4、Lucide、Motion、dnd-kit 和 Recharts 3，以现有 React 19 / Vite / Electron 工程增量迁移。交付实际组件源码、依赖及锁文件、主题 CSS、组件配置和真实窗口中的可操作示例。单纯罗列依赖或画出相似外观不满足本任务。

## 实施要点

1. 定义语义颜色及深浅色值、字体/字号/行高/400-500-600 字重、数字排版、间距、圆角、控件尺寸、边框、阴影、层级、动效；映射 Tailwind 与 shadcn 所需变量。
2. 按需引入 Button、Input、Label/Field、Badge、Card、Separator、Progress、Skeleton；同时建立后续所需 Dialog/Sheet、AlertDialog、Select、Popover、DropdownMenu、Tooltip、Tabs、Collapsible、Switch、通知的统一约定。
3. 明确选择 Base UI 版本与 Mira 风格，核对当前 CLI / registry 的配置及 React 19 兼容版本，不混搭不同 primitives。实际使用版本、初始化参数与来源记录到共同设计的实施记录或本 Issue。
4. 将主题同步到 html，使 body Portal 获得同一主题；处理 overlay、菜单、Toast 的层级和 reduced-motion。
5. 处理旧全局按钮/输入选择器和 CSS layer 优先级。旧变量可临时映射新变量，页面不能新增裸色值与任意字重来补丁式覆盖。
6. Lucide 按需导入，定义统一图标尺寸、描边与命名；`components/ui.tsx` 业务辅助函数与新 UI 目录的职责清楚。
7. 接入 Motion 与 dnd-kit，为 FE-014 明确动画配置、减少动效和排序接入方式；由 FE-014 在实际卡片中使用，不重新实现拖拽基础。
8. 接入 shadcn Chart / Recharts 3 的 ChartContainer、Tooltip、Legend，定义图表主题 Token。在已有预览工具内放置明确标为“组件示例”的固定数据图表，能够切换主题和查看 Tooltip；不伪装为实际消费统计。

## 验收方法

- 在应用内临时开发预览区域或已有预览工具中检查按钮、输入、Badge、Progress、Dialog 内 Select；不建立独立 Storybook。
- 同时查看默认、hover、focus-visible、disabled、loading、error；切换深浅色时弹层与页面一起变化，没有白底黑字错配。
- 修改一个颜色/圆角/字重 Token，使用它的代表组件同步变化；数值来自单一源。
- 原页面在迁移期仍可打开，表单输入可读；`npm run typecheck` 通过，打开真实 Electron 验证基础样式与 Portal。
- 记录普通文字及焦点/必要控件边界的实际对比度；用真实背景组合校正 Token，不只检查孤立色板。
- 能从实际导入和组件配置确认 Mira / Base UI；Recharts 示例能在真实窗口渲染，包含 Tooltip、Legend、空数据与窄宽度检查。Motion / dnd-kit 的实际业务使用点由 FE-014 交付并在 FE-018 汇总。

## 关联与责任

解除 FE-013、FE-015、FE-016、FE-017 的前置。基础负责人拥有依赖、Token、基础 UI、主题入口和全局兼容层；后续页面通过统一 variants 调整。
